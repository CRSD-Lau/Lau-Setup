# 安装人员审查

作者：Neil Mitchell  
创建者： Neil Mitchell  
最后修改者：Neil Mitchell

根据 GStack 审查清单审查了新应用程序，包括独立的只读安全审查。所有已确定的实施问题均已在授权安装人员的工作中得到解决：

- 丢失的可执行文件可能会阻止选择客户端进行崩溃恢复。现在，文件夹选择会在检查 WoW.exe 之前发现并验证恢复记录。 GUI 回归测试涵盖了缺少可执行文件的情况。
- 下载发生在操作锁定之前。现在，一项租约通过提交涵盖了下载缓存；在该租约内检查待恢复。
- 可预测的可写临时文件可以遵循 NTFS 硬链接。日志和程序集临时文件现在使用带有 CreateNew 的 GUID 名称。恢复的部分文件以独占方式打开，并在任何截断或写入之前检查其链接计数。实际的硬链接回归测试证明不相关的文件保持不变。
- 被篡改的恢复日志可能会在验证之前在另一个根下创建锁。现在，在获取恢复锁之前会验证大小、位置、根目录、区域设置、条目和范围路径。回归测试证明没有创建外来锁。
- 中断恢复没有自己的可恢复状态。 RESTORING 在突变之前被记录并在整个 UI 和恢复路径中被识别。每个恢复步骤通过后进行故障注入。
- 安装/恢复的地图选项可能在用户界面中保持陈旧。每次成功操作后都会刷新客户端检测。 GUI 测试安装地图选择、验证其保留状态、恢复并验证先前状态。

GitHub 迁移还会将存储库、发布标签和文件名固定在嵌入式目录中。重定向是手动进行的，因此在请求之前会检查每个 HTTPS 目标，包括凭据和端口检查。旧的 Google Drive HTML 确认解析器已被删除。添加的测试涵盖目录 URL 篡改、重定向可恢复传输和拒绝的重定向目标。

对迁移的独立审查发现，Python 优化可以删除以断言形式编写的发布检查。上传、目录刷新和发布门检查现在会引发明确的异常。上传程序还解析每个源并要求其直​​接保留在有效负载目录中。发布防护测试通过了 `python -O` 下的文件路径、大小、哈希值和远程 URL/摘要篡改。

最新完整回归套件：`reports/tests-20260911-200603/results.json`； 38 测试组通过，包括 108 实际夹具安装/恢复组合、所有提交/恢复中断点、路径/连接/硬链接保护、进程和文件锁定、损坏/漂移、HTTP 范围处理、取消、离线汇编以及使用真实版本可执行文件的 GUI 安装/恢复。

1.0.1 UI 审查涵盖更明亮的支持文本、更大的页脚文本和自定义禁用控件绘画。 Native Enabled 语义保持不变；仅手动绘制禁用外观。对初始、就绪和繁忙的 Windows 预览进行了目视检查。 Core.cs、Downloader.cs 和所有游戏负载与 v1.0.0 的字节相同。其游戏/网络证据被保留；为此更新重新运行 Windows 回归套件。 Wine可行性探针未通过表单构建，未建立平台支持。

发布检查和最终二进制元数据是单独的门。请参阅版本 VALIDATION.json 了解证据范围，包括从未更改的游戏基线中保留的检查。
