# Обзор установщика

Автор: Neil Mitchell  
Создатель: Neil Mitchell  
Последнее изменение: Neil Mitchell

Проверил новое приложение на соответствие контрольному списку проверки GStack, включая независимую проверку безопасности только для чтения. Все выявленные проблемы реализации были решены в рамках работы авторизованного установщика:

- Отсутствующий исполняемый файл может помешать выбору клиента для восстановления после сбоя. Выбор папки теперь обнаруживает и проверяет записи восстановления перед проверкой WoW.exe. Регрессионный тест графического интерфейса охватывает случай отсутствия исполняемого файла.
- Загрузки происходили до блокировки работы. Одна аренда теперь покрывает кэш загрузки через фиксацию; ожидающее восстановления проверяется внутри этой аренды.
- Предсказуемые временные файлы с возможностью записи могут следовать за жесткими ссылками NTFS. Временные файлы журнала и сборки теперь используют имена GUID с CreateNew. Возобновленные частичные файлы открываются исключительно, и их количество ссылок проверяется перед усечением или записью. Фактический регрессионный тест жестких ссылок доказывает, что несвязанный файл остается неизменным.
- Подделанный журнал восстановления может создать блокировку под другим корнем перед проверкой. Размер, местоположение, корень, языковой стандарт, записи и пути к области действия теперь проверяются перед получением блокировки восстановления. Регрессионный тест показывает, что внешняя блокировка не создается.
- Прерванное восстановление не имело собственного возобновляемого состояния. ВОССТАНОВЛЕНИЕ записывается в журнал перед мутацией и распознается на протяжении всего пользовательского интерфейса и пути восстановления. Внедрение ошибок после прохождения каждого шага восстановления.
- Установленные/восстановленные параметры карты могли оставаться устаревшими в пользовательском интерфейсе. Обнаружение клиента обновляется после каждой успешной операции. Тест GUI устанавливает выбранную карту, проверяет ее сохраненное состояние, восстанавливает и проверяет предыдущее состояние.

Миграция GitHub дополнительно закрепляет репозиторий, тег выпуска и имя файла во встроенном каталоге. Перенаправления выполняются вручную, поэтому каждый пункт назначения HTTPS проверяется перед запросом, включая проверку учетных данных и портов. Старый анализатор HTML-подтверждений Google Диска был удален. Добавлены тесты, охватывающие подделку URL-адреса каталога, перенаправленную возобновляемую передачу и отклоненные пункты назначения перенаправления.

Независимый обзор миграции показал, что оптимизация Python может удалить проверки публикации, записанные в виде утверждений. Проверки загрузки, обновления каталога и выпуска теперь вызывают явные исключения. Загрузчик также разрешает каждый источник и требует, чтобы он оставался непосредственно внутри каталога полезных данных. Тесты защиты публикации проходят под `python -O` на предмет путей к файлам, размеров, хэшей и удаленного изменения URL-адресов/дайджестов.

Последний полный пакет регрессии: `reports/tests-20260911-200603/results.json`; Группы тестов 38 пройдены, включая 108 фактические комбинации установки/восстановления приспособлений, все точки прерывания фиксации/восстановления, защиту пути/соединения/жестких ссылок, блокировки процессов и файлов, повреждение/дрейф, обработку диапазона HTTP, отмену, автономную сборку и установку/восстановление графического пользовательского интерфейса с использованием исполняемого файла с реальной версией.

Обзор пользовательского интерфейса 1.0.1 охватывает более яркий вспомогательный текст, более крупный текст нижнего колонтитула и настраиваемую отрисовку элементов управления с отключением. Семантика Native Enabled остается на месте; только отключенный внешний вид рисуется вручную. Первоначальные, готовые и загруженные превью Windows были визуально проверены. Core.cs, Downloader.cs и все полезные данные игры остаются байтово-идентичными v1.0.0. Его игровые/сетевые данные сохраняются; для этого обновления повторно запускается пакет регрессии Windows. Технико-экономическое обоснование Wine не прошло этап строительства и не устанавливает опору платформы.

Проверки публикаций и окончательные двоичные метаданные — это отдельные шлюзы. См. выпуск VALIDATION.json, чтобы узнать об объеме доказательств, в том числе о том, какие проверки были сохранены из неизмененной базовой версии игры.

## Настройка 1.1.7 обзор

Просмотрены текущие различия для области пути, доверия к локальному источнику, выбора загрузки, предпечатной проверки/фиксации отклонения, резервного копирования транзакций и совместимости отката. Никаких нерешенных выводов. Локальное повторное использование ограничивается парой S, соответствующей каталогу: корневой/активный языковой стандарт; отключенные файлы перемещаются через существующий проверенный журнал резервного копирования. Обе платформы прошли регрессионные группы 50 и включили/выключили/включили фактический файл выпуска с точным откатом стека. Полезная нагрузка игры не меняется.
