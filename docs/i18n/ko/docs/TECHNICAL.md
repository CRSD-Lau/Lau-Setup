## 빌드 및 검증

.NET Framework 컴파일러가 설치된 Windows에서 `tools/build.ps1`를 실행합니다. 공개 소스 번들에는 애플리케이션, 포함된 카탈로그, 빌드 스크립트 및 문서가 포함되어 있습니다. 전체 개발 체크아웃에는 트랜잭션, 다운로드, 경로, 프로세스, 복구 및 GUI 회귀 테스트를 위한 `tools/test.ps1`가 추가로 포함되어 있습니다. 이러한 테스트에서는 격리된 고정 장치와 로컬 참조 실행 파일을 사용합니다. `tools/build.ps1 -Release`는 출판 게이트를 통과하지 못한 카탈로그를 거부합니다. 테스트 하네스, 페이로드 생성 및 기본 게임 테스트는 비공개 로컬 소스 경로에 따라 달라지며 공개 소스 번들의 일부가 아닙니다.

`build/catalog.json`는 관찰된 GitHub 릴리스 URL과 함께 크기 및 SHA-256별로 모든 자산 및 다운로드 세그먼트의 이름을 지정합니다. 카탈로그는 저장소, 릴리스 태그 및 해시 이름 파일을 고정합니다. 설치 프로그램은 익명으로 다운로드하고 리디렉션을 따르기 전에 모든 리디렉션을 확인합니다. 설치 프로그램에는 GitHub 계정, 로그인된 브라우저 또는 API 자격 증명이 필요하지 않습니다. 전체 개발 체크아웃에서 `tools/refresh_github_catalog.py`는 해시를 변경하지 않고 업로드된 자산을 연결하고, `tools/verify-public.ps1`는 ​​앱에서 사용하는 것과 동일한 다운로더를 통해 모든 세그먼트와 재구성된 자산을 확인합니다.

## 파일 배치

| 구성요소 | 목적지 |
|---|---|
| 호환 가능한 실행 파일 | `WoW.exe` |
| 선정된 지역 Q | 루트 `Data/patch-q.mpq` 및 활성 로케일 `Data/<locale>/patch-<locale>-Q.MPQ`의 동일한 복사본 |
| 선택된 에디션 Y | 루트 `Data/patch-y.mpq` 및 활성 로케일 `Data/<locale>/patch-<locale>-Y.MPQ`의 동일한 복사본 |
| 새로운 주문 자산(선택 시) | 루트 `Data/patch-s.mpq` |
| 선택 시 현지화된 철자표 일치 | 활성 로케일 `Data/<locale>/patch-<locale>-S.MPQ` |
| 선택적 지도/미니맵 | 루트 `Data/patch-m.mpq`; 대체된 활성 로캘 M이 백업되었습니다. |

Core Q는 릴리스의 LoadingScreens.dbc, 현지화된 Map.dbc 및 바이트 단위로 이미지 로드를 유지합니다. 추가된 세계 지도 정의와 세계 지도 아트워크가 생략되었습니다. 전체 지도 모드는 원래 지역 Q와 공유 M을 다시 압축하지 않고 사용합니다. 두 개의 S 배치에는 서로 다른 아카이브가 포함되어 있습니다. 새로운 주문을 끄면 범위가 지정된 루트/로캘 S 쌍이 .mpq.disabled로 유지됩니다. 다시 활성화하면 아래 1.1.7 설정 섹션에 설명된 대로 비활성화된 일반 복사본이 확인된 트랜잭션 백업으로 이동됩니다. HD 감지에는 일치하는 기존 루트 및 로케일 F 패치가 필요합니다.

<a id="recovery-design"></a>

## 복구 설계

하나의 클라이언트 잠금에는 다운로드, 준비 및 설치가 포함됩니다. 파일은 스테이징 전과 배치 후에 다시 확인됩니다. 기존 파일은 `LauSetupBackups/transactions/<id>/before/`로 이동하여 바이트와 타임스탬프를 보존합니다. 저널은 커밋 전에 지속적으로 작성됩니다. 실패한 커밋은 안전할 때 원본을 복원합니다. 중단된 커밋 및 중단된 복원은 WoW.exe 없이도 앱을 다시 열 때 검색 가능한 상태로 유지됩니다.

복원은 다른 업데이트로 변경된 파일을 거부하고 수동 해결을 위해 백업을 유지합니다. 정확한 루트/활성 로캘 Q/M/S/Y 경로와 WoW.exe만 허용됩니다. 순회, 대체 스트림 및 재분석 지점이 거부됩니다. 쓰기 가능한 재개된 파일에는 하나의 하드링크가 있어야 합니다. 저널 및 어셈블리 임시는 고유한 이름과 독점 생성을 사용합니다. 애플리케이션은 클라이언트 파일 시스템에 아카이브를 열거하지 않습니다.

<a id="release-boundaries"></a>

## 릴리스 경계

이 설치 프로그램에는 디지털 서명이 없습니다. Windows 및 Wine 설치 프로그램 테스트, 샘플링된 GUI 검사 및 유지된 게임 데이터 기준은 VALIDATION.json에 별도로 기록됩니다. Wine 1.1.0 검사는 Wine 11.0 / Wine Mono 10.4.1 및 로컬 Docker 오버레이 스토리지를 사용합니다. 중첩 마운트 테스트는 해당 컨테이너가 마운트를 생성할 수 없기 때문에 장치 ID를 모의합니다. 이러한 검사는 모든 Linux 배포/파일 시스템, 디스플레이 규모, 만남 또는 타사 클라이언트 수정을 인증하지 않습니다. 원시 Patch-Y 에디션 ZIP은 GitHub 릴리스에서 사용할 수 있습니다. 현재 범위 및 가정은 [알려진 제한 사항](../KNOWN-LIMITATIONS.md)을 참조하세요.

## 1.1.5 설정 비활성화 Patch-S 보존

루트 및 활성 로캘 S 경로에만 .disabled 접미사가 붙습니다. 비활성화할 때마다 S를 비활성화하기 전에 해시 고정된 로컬 단계적 복사본이 생성됩니다. 두 경로 모두 저널링되며 최대 11개의 대상이 있습니다. 롤백은 원래 활성 파일을 복원하고 새로 생성된 비활성화된 복사본만 제거합니다. 기존의 동일한 비활성화된 복사본은 트랜잭션 외부에 남아 보존됩니다. 충돌하는 파일 또는 디렉터리 블록 계획. 재활성화하면 카탈로그 S 자산이 설치되고 비활성화된 복사본은 사용되지 않습니다. 기존 저널은 계속 읽을 수 있습니다. 임의의 로컬 소스 경로는 허용되지 않습니다. 각 로컬 복사본은 쌍을 이루는 S 비활성화 작업과 일치해야 합니다.

## 1.1.6 비활성화-복사 충돌 설정

현재 활성 S 파일은 항상 일반 .mpq.disabled 이름을 사용합니다. 기존의 다른 비활성화된 파일을 바꾸기 전에 설치 프로그램은 해당 바이트를 SHA-256의 첫 번째 12 문자로 끝나는 형제로 준비합니다. 재사용하기 전에 전체 SHA-256 및 길이를 확인합니다. 이는 기존 Windows 경로 제한 내에서 이름을 유지합니다. 충돌하는 아카이브 콘텐츠가 실패하여 종료되었습니다. 활성 S, 일반 비활성화 파일 및 새로 생성된 보관 복사본은 최대 13개 항목으로 독립적으로 저널링됩니다. 롤백은 모든 원본을 복원합니다. 로컬 소스는 페어링된 S 비활성화 또는 비활성화된 파일 교체 작업으로 제한됩니다. 오래된 저널은 여전히 ​​읽을 수 있습니다.

## 1.1.7 설정 정리를 다시 활성화

새로운 주문 저널을 활성화하면 일반 루트 및 활성 로캘이 비활성화된 S 파일이 제거됩니다. 트랜잭션은 확인된 원본 바이트를 데이터 외부의 백업 전 트랜잭션으로 이동합니다. 비활성화된 파일이 카탈로그 SHA-256 및 크기와 일치하는 경우 해당 파일은 일치하는 S 대상에 대해 로컬로 준비되고 다운로드에서 제외됩니다. 로컬 소스는 정확한 비활성화된 파일 제거 및 카탈로그 자산과 쌍을 이루어야 합니다. 이미 일치하는 Active S는 여전히 정리 트랜잭션을 생성합니다. 기존 해시 접미사 아카이브는 정리되지 않습니다. 이전 저널은 계속 읽을 수 있습니다. 켜기/끄기/켜기, 소스 드리프트, 모든 새로운 커밋/복원 단계의 중단, 모든 로케일 및 스택 복원이 포함됩니다.
