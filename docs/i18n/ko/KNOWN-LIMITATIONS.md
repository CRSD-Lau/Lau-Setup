# 알려진 제한 사항 및 가정



[Lau Setup로 돌아가기](README.md) · [권장사항 및 기능 요청](https://github.com/CRSD-Lau/Lau-Setup/discussions/1) · [DBC 변경 내역](DBC-CHANGELOG.md)

기능을 제안하기 전에 이 내용을 읽어보세요. Lau Setup는 **WoW 3.3.5a 빌드 12340**에 대한 클라이언트 측 시각적 업그레이드를 설치합니다. 서버 수정 프레임워크가 아닙니다. 아래 경계는 현재 프로젝트를 설명합니다. 범위를 벗어난다고 해서 반드시 기술적으로 불가능하다는 의미는 아닙니다.

<a id="what-we-can-and-cannot-change"></a>

## 바꿀 수 있는 것과 바꿀 수 없는 것

| 요청 | 현재 경계 |
| --- | --- |
| 지원되는 지상 표시기, 텍스처, 모델 또는 현지화된 클라이언트 테이블 개선 | 범위 내에서는 파일 종속성 및 테스트가 적용됩니다. 시각적인 개선을 서버 손상이나 메커니즘의 변경으로 설명해서는 안 됩니다. |
| 설치, 백업, 접근성 또는 문서화 개선 | 범위 내. 관련 없는 파일을 보존하고 설치 및 복구를 확인합니다. |
| Warmane 피해, 적중 감지, 능력 지속 시간, 타겟팅 또는 조우 스크립트 변경 | 우리의 통제 밖에 있습니다. Warmane는 자체 서버 코드를 실행합니다. 이 프로젝트에는 해당 코드를 변경하거나 배포할 수 있는 액세스 권한이 없습니다. MPQ나 애드온은 서버가 다른 메커니즘을 채택하도록 만들 수 없습니다. |
| Warmane의 코어에 사용자 정의 C++ 코드 추가 | 이번 릴리스에서는 제공할 수 있는 것이 없습니다. 별도로 제어되는 테스트 서버를 변경해도 Warmane는 ​​변경되지 않습니다. |
| DLL 삽입, 클라이언트 연결 또는 새 기본 엔진 동작 추가 | 지원되는 패치/애드온 작업 흐름 외부. 이를 위해서는 단순한 DBC 편집이 아닌 별도의 엔지니어링 및 호환성 조사가 필요합니다. DLL 주입 프레임워크나 일반 클라이언트 후크 지원은 제공되지 않습니다. |
| 보호된 Lua 작업 또는 누락된 게임 API 잠금 해제 | 지원되는 기능이 아닙니다. 편집 가능한 애드온 Lua와 보호된 클라이언트 작업은 다릅니다. Lua를 다시 작성한다고 해서 자체적으로 권한을 부여하거나 클라이언트가 노출하지 않는 API를 생성하지는 않습니다. 해결 방법이 있다고 가정하기 전에 정확한 작업/API를 보고하세요. |
| 전체 클라이언트, 다른 언어 팩 또는 HD 모델 기반 제공 | 포함되지 않습니다. 필요한 언어 파일, 글꼴 및 모델 구성을 갖춘 기존 호환 클라이언트를 가져옵니다. |

설정에서 제공되는 호환 가능한 `WoW.exe`는 승인된 로딩 렌더러, 아카이브 용량 및 대규모 주소 지원에서 특정 역할을 합니다. 이 포함은 임의 실행 파일이나 DLL 수정을 약속하는 것이 **아닙니다**. 마찬가지로 모든 Lua 파일이 보호되거나 편집 불가능한 것은 아닙니다. 클라이언트가 지원하는 동작 내에서 일반적인 애드온 및 UI 변경이 가능할 수 있습니다.

<a id="indicators-are-visual-guidance"></a>

## 지표는 시각적 안내입니다.

- **Warmane는 Warmane 보고서에 대한 런타임 참조입니다.** AzerothCore 및 격리된 클라이언트는 해당 환경에서 파일 무결성과 동작을 확인하는 데 도움이 됩니다. Warmane의 사용자 지정 적중 감지, 타이밍 또는 조우 동작을 증명할 수 없습니다.
- **그려진 가장자리는 안전한 경계를 보장하지 않습니다.** 지원되는 호흡 및 점액 스프레이는 테스터 피드백에 따라 90° 총 원뿔을 사용합니다. Halion meteor-fire는 승인된 test-v2 확대를 사용합니다. 이는 Warmane 서버 소스의 측정값이 아닌 관찰을 기반으로 한 시각적 경고입니다.
- **지형은 평평한 표시기를 자를 수 있습니다.** 평평한 지면 메시는 경사면, 계단 및 울퉁불퉁한 표면을 교차할 수 있습니다. 확대하거나 높이는 것은 모든 곳에서 지형을 따르는 투영을 보장하지 않습니다.
- **효과 수명은 증거를 만나야 합니다.** 추적/유령 피드백에는 1~2초 후에 사라지는 효과가 포함되어 있습니다. 텍스처, 모양 또는 반복 애니메이션을 변경하는 것만으로는 클라이언트가 전체 추구를 위해 효과 인스턴스를 활성 상태로 유지한다는 것을 증명할 수 없습니다. 타이밍 수정에는 해당 특정 능력에 대한 영상과 사건 증거가 필요합니다. 모형 또는 실험적 빌드를 확인된 수정 사항으로 취급하지 마십시오.
- **모형은 예시입니다.** 웹사이트/채팅 애니메이션은 외관을 보여줍니다. 이는 게임 내 렌더링, 지속 시간 또는 적용 범위에 대한 녹음이나 증거가 아닙니다.

경계 또는 타이밍 보고서의 경우 조우, 능력, 난이도, 클라이언트 버전, `/pyversion` 및 리드업 및 손상 또는 효과 종료를 보여주는 클립을 포함합니다. 스크린샷은 유용하지만 원근감과 중첩 효과로 인해 정확한 반경 측정이 제한됩니다.

<a id="dbc-and-patch-compatibility"></a>

## DBC 및 패치 호환성

DBC 테이블은 독립된 스위치가 아닌 연결된 데이터입니다. 비주얼을 추가하려면 일치하는 주문, 비주얼, 키트, 효과 및 모델 참조가 필요할 수 있습니다. 전체 테이블을 바꾸면 현지화된 텍스트도 바뀌고 동일한 테이블을 제공하는 다른 패치와 충돌할 수 있습니다.

이 프로젝트를 개발하는 동안 현지화 종속성은 실제 문제였습니다. Andre와 Lau가 함께 작업했습니다. [과거 DBC 감사](DBC-CHANGELOG.md)는 보고된 개발 타임라인을 보관된 아카이브 증거와 분리합니다. Andre의 기준선은 모든 DBC가 아니라 `Spell.dbc`를 생략했습니다. 영어 테이블을 다른 로케일로 복사하는 것이 안전하다고 가정하지 마십시오.

- 현재 HD/원래 모델 구성과 일치하는 에디션을 사용하세요. 새로운 주문 비주얼에는 호환 가능한 HD 종속성이 필요합니다. 감지 기능이 모든 타사 모델 팩을 인증하는 것은 아닙니다.
- 설치 후 HD 모델 패치를 제거하거나 비활성화하는 경우 결과 구성에 대한 최신 설정을 다시 실행하십시오. 설치된 HD 에디션은 동적으로 자체 변환되지 않습니다. 일치하지 않는 자산은 누락되거나 잘못된 시각적 개체를 생성할 수 있으며 충돌 조사가 필요할 수 있습니다. 충돌이나 충돌 없는 동작은 보장되지 않습니다.
- 루트 및 활성 로캘 배치에는 서로 다른 역할이 있습니다. 특히 두 S 아카이브는 서로 다르다. 모든 MPQ를 복제하려면 일반적인 지침이 아닌 [배치 가이드](docs/TECHNICAL.md#file-placement)를 따르세요.
- 관련되지 않은 패치는 보존되지만 보존한다고 해서 호환성이 보장되는 것은 아닙니다. 동일한 데이터를 재정의하는 다른 아카이브로 인해 결과가 변경될 수 있습니다.
- 설치 프로그램 인터페이스는 열 가지 옵션 중 운영 체제 언어를 자동으로 따르며 수동 선택은 저장됩니다. 게임 콘텐츠는 계속 9개 로케일을 지원합니다. `Config.wtf`만 변경해도 다른 언어의 파일이나 글꼴은 설치되지 않습니다.

<a id="installer-and-recovery-assumptions"></a>

## 설치 프로그램 및 복구 가정

설치 또는 복원하기 전에 WoW를 완전히 닫으십시오. 정확한 의도된 클라이언트 폴더를 사용하고 `LauSetupBackups`를 그대로 유지하십시오.

설치 프로그램은 실제 파일 해시를 **포함된 카탈로그**와 비교합니다. 크기와 타임스탬프가 일치하는 경우에도 1바이트 변경 사항을 감지할 수 있지만 이전 설치 프로그램은 여전히 ​​이전 카탈로그만 알고 있습니다. 업그레이드할 때 최신 설치 프로그램을 다운로드하세요. 설치 프로그램은 클라이언트가 종료된 후 지속적으로 클라이언트를 모니터링하지 않거나 나중에 수동 패치 변경 사항을 자동으로 조정하지 않습니다.

새로운 주문 시각 효과를 끄면 범위가 지정된 S 파일이 `.mpq.disabled`로 보존됩니다. 재활성화는 사용 가능한 경우 일치하는 비활성화된 바이트를 사용하고 일반 비활성화된 복사본을 확인된 트랜잭션 백업으로 이동합니다. 이전 해시 접미사 복사본은 유지됩니다. [현재 복구 구현](docs/TECHNICAL.md#setup-117-re-enable-cleanup)을 참조하세요.

복원은 백업 및 복구 기록에 따라 다릅니다. 나중에 변경하여 자동 복원이 안전하지 않게 되면 중지됩니다. 백업만 삭제된 파일의 복구를 약속할 수는 없습니다. Patch-Y만 제거하는 것은 실행 파일과 설치 프로그램에 의해 설치된 기타 패치의 전체 롤백이 아닙니다. 관리되는 트랜잭션에는 **이전 설치 복원**을 사용하세요.

<a id="platform-and-validation-limits"></a>

## 플랫폼 및 유효성 검사 제한

문서화된 Windows 대상은 .NET Framework 4.8를 사용하는 Windows 10/11입니다. 테스트된 Linux 구성은 Wine 11.0, Wine Mono 10.4.1, 기존 64-bit 접두사 및 Python 3.9+를 사용합니다. 런타임 설치 프로그램은 번들로 제공되지 않습니다. [Wine 전제조건](wine/README.md)을 따르십시오. 로컬 Linux 스토리지를 사용합니다. 연결된 폴더, 네트워크 공유 및 Windows 탑재 드라이브는 지원되는 Wine 경로 구성 외부에 있습니다.

Lutris, Proton, Steam Deck 관련 통합 및 macOS는 이번 릴리스에서 통합 대상을 지원하지 않습니다. 이것은 다른 모든 환경이 불가능하다고 주장하는 것이 아닙니다. 이는 우리가 이에 대한 지원을 설정하지 않았음을 의미합니다. Windows 패키지에는 디지털 서명이 없습니다.

빌드, 해시 확인, 설치 프로그램 회귀 테스트, Wine 테스트 및 게임 내 테스트는 다양한 질문에 답합니다. 하나를 통과해도 다른 것을 대체할 수는 없습니다. 모든 영역, 만남, 디스플레이 규모, Linux 배포 또는 타사 클라이언트 수정에 대한 인증이 아닌 시각적 검사가 샘플링됩니다. 실제로 확인된 내용은 각 릴리스의 검증 보고서를 참조하세요.

<a id="before-requesting-a-feature"></a>

## 기능을 요청하기 전에

플레이어에게 보이는 문제, 설정 및 증거를 설명하십시오. 지원 범위 내의 제안은 [아이디어](https://github.com/CRSD-Lau/Lau-Setup/discussions/categories/ideas)에서 환영합니다. 재현 가능한 결함은 [문제](https://github.com/CRSD-Lau/Lau-Setup/issues/new/choose)에 속합니다.

DLL, 네이티브 코드, 보호 작업 또는 서버 종속 제안의 경우 종속성을 명시적으로 식별합니다. 구현을 약속하기 전에 영향을 받는 시스템에 대한 타당성 조사와 적절한 제어가 필요합니다. 단순 누락된 DBC 옵션으로 분류하지 마십시오.
